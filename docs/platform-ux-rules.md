# Platform UX Rules

Purpose: adapt `ehmo/platform-design-skills` to this project surface map.

## Google Sheet

- Treat the Sheet as the operating control room.
- Keep stable IDs visible: video IDs, candidate IDs, task IDs, short IDs.
- Put status, owner, next action, and review state near the left side.
- Avoid decorative or narrative columns that slow scanning.
- Do not hide guardrail, approval, or compliance state.

## Daily Markdown Report

- The first screen should answer: what happened, what matters, what to do next.
- Keep risks and blockers visible.
- Prefer one recommended action over a long idea list.
- Link or name the full output files instead of copying every detail.

## Telegram

- One message should usually contain one primary action.
- Use short commands or keywords such as `CHECKLIST`, `/report`, `/next`.
- Never include secrets, private credentials, or private lead details.
- Broadcasts, offers, and publish-like actions require human approval.

## Dashboard / Web

- Operational dashboard first, marketing page never.
- KPI, trend, blocker, and next action must be visible without hunting.
- Use dense but calm layouts for repeated daily use.
- Accessibility and readability matter more than decorative visual style.

## Review Checklist

- Is the target surface clear?
- Is the next action visible?
- Are IDs and statuses stable?
- Are risks and approval states visible?
- Would a busy operator know what to do in under 30 seconds?
